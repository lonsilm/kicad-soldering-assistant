# v1.3.0 验证

在 Windows、KiCad 10.0.6 环境完成以下验证。测试报告和生成的工程数据仅保存在本机 `tests/results/`，不提交到仓库。

- 编译为 Windows GUI 子系统的单个 EXE；复制到仅有这一文件的新文件夹后正常运行。
- 路径包含中文、空格、单引号和 `&` 时，仍可读取工程和生成页面。
- 完成合成板以及两个真实工程的只读生成；生成前后源文件 SHA256 一致。
- 待焊清单正确排除 DNP、显式不计入 BOM 的器件和机械对象。
- 内置运行缓存被改坏后，EXE 能从自身资源恢复并成功生成。
- 同一工程重新生成保持输出标识，最近记录不重复。
- 多板目录要求选择目标；路径不存在或文件类型不支持时显示错误。
- 实际由 EXE 生成的 HTML 已用 Headless Edge/Playwright 验证：位号定位、进度保存与重载、JSON备份恢复、正反面切换、1280px窗口布局和零外部网络请求。

`.github/workflows/build-windows.yml` 提供手动构建入口，不会自动执行上述需要本机 KiCad 的实板测试。

- EXE 内嵌 WebView2 工作区；生成后和打开最近工程时均不通过 Shell 打开 HTML。
- 已在实际复制的单文件 EXE 内执行搜索定位、正反面切换、进度保存、原生备份/恢复按钮、导出下载及工程存储隔离验证。
- 关闭并重新启动 EXE 后，应用专用 WebView2 配置中的进度仍然保留。
- 工作区使用映射到本机输出的虚拟域名；页面无需网络，外部资源请求被拦截。
- 使用内嵌控件自身的 CapturePreview API 检查真实 FOC/TC377 工作区显示；未使用 computer-use。
- 旧版浏览器进度可通过同格式 JSON 备份迁移到应用内；二者配置存储独立。

- 检查 1024×768、1280×800、1920×1080 窗口的左右及上下布局：板图区不掉到清单下方、不越出窗口，滚动限制在分栏内。
- 检查明暗主题文本颜色和键盘搜索快捷键；原生启动页与内嵌真实板图均通过程序自身的绘图/截图 API 检查，无 computer-use。
- 验证旧版缓存界面自动更新：只替换工具生成页面的样式与交互代码，板图数据和工程元数据保持一致，原有进度保留。
